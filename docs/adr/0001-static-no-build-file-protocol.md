**Контекст**
Бриф требует «html, css, js» и «максимально простой» сайт. Хостинг выбран пользователем — GitHub Pages. Владелец должен открывать сайт двойным кликом по `index.html`, без сервера.

**Решение**
Сайт — статика на чистых HTML/CSS/JS без фреймворков, сборки и зависимостей в рантайме. Все скрипты подключаются классическими `<script src>` и регистрируются в общем пространстве имён `window.ECA`. ES-модули и `fetch` локальных файлов не используются.

**Почему**
- Фреймворк или бандлер (React, Vite и т. п.) отвергнуты: бриф прямо требует чистый HTML/CSS/JS. Кроме того, сборка — лишний шаг, который автор канала не сможет повторить сам после правки контента.
- ES-модули (`type="module"`) отвергнуты: Chrome блокирует их загрузку со схемы `file://` из-за CORS, и двойной клик по `index.html` давал бы пустую страницу.
- Вариант «сайт работает только через локальный сервер» (`npx serve` и т. п.) отвергнут: он ломает сценарий «открыл файл — работает» и требует от владельца терминала.

**Последствия**
- Нет изоляции модулей: всё живёт в одном глобальном `ECA`, порядок `<script>` в `index.html` важен, а зависимости между файлами никто не проверяет.
- Нет tree-shaking и минификации: весь код и контент грузятся целиком. При нынешнем объёме (≈ 200–300 КБ) это приемлемо.
- Нельзя подключать npm-библиотеки как есть — только самописное или вендоренное вручную.
- Любое будущее решение, которому нужен `fetch` или модули, сначала упрётся в это ограничение `file://`.
