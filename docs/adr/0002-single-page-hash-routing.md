**Контекст**
В сайте много экранов (уровень, тема слов, тест, тема грамматики). Кнопка «назад» и ссылки на конкретную тему должны работать и на `file://`, и на GitHub Pages (ADR 0001).

**Решение**
Сайт — одна страница `index.html`, экраны переключаются через hash-роутинг (`#/a1`, `#/a1/words/<id>`, `#/a1/grammar/<id>`). Каждый экран имеет свой адрес.

**Почему**
- History API (`pushState`, адреса вида `/a1/words/...`) отвергнут: на `file://` он не работает. На GitHub Pages прямой заход по такому адресу даёт 404, если не настроить хак с `404.html`.
- Отдельный HTML-файл на экран отвергнут: шапку, футер, переключатели языка и темы пришлось бы дублировать в десятках файлов или генерировать сборкой, которой нет. К тому же страницу для каждой из ~80 тем пришлось бы заводить вручную.
- Одна страница без адресов (только состояние в памяти) отвергнута: не работали бы «назад», перезагрузка на том же экране и ссылки на тему.

**Последствия**
- Адреса с `#` выглядят менее «чисто», а поисковики индексируют их как одну страницу. SEO по отдельным темам фактически нет.
- Фокус, прокрутку и заголовок экрана при переходе приходится обрабатывать вручную — браузер этого за SPA не делает.
- Маршруты становятся публичным контрактом: переименование `topicId` ломает уже разосланные ссылки. Для этого нужен экран «Такой темы нет».
- Перейти позже на «чистые» адреса значит поменять все ссылки и отказаться от `file://`.
