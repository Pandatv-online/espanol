**Контекст**
Контента много (~700 слов, ~27 тем грамматики, шесть уровней), и автор канала будет дописывать его сам, не трогая дизайн. `fetch` локальных файлов на `file://` недоступен (ADR 0001).

**Решение**
Контент лежит в JS-файлах данных, по файлу на уровень и раздел (`data/vocab-a1.js`, `data/grammar-a1.js`, …). Каждый файл регистрирует свои темы вызовом `ECA.data.addVocab(...)` / `addGrammar(...)`. Корректность проверяет отдельный валидатор `node tools/validate-content.js`.

**Почему**
- JSON + `fetch` отвергнут: на `file://` запрос к локальному файлу блокируется, и сайт не открылся бы двойным кликом.
- Один большой файл со всем контентом отвергнут: это тысячи строк, в которых автору трудно найти нужное, а одна синтаксическая ошибка роняет все уровни сразу.
- Контент прямо в HTML-разметке отвергнут: он смешался бы с дизайном, и перевод RU/EN, прогресс и тесты пришлось бы вытаскивать из DOM.
- Markdown/YAML отвергнуты: для них нужен парсер или шаг сборки, а сборки нет.

**Последствия**
- Автор правит JavaScript, а не «просто данные»: пропущенная запятая или кавычка ломает файл. Поэтому нужны валидатор с понятным сообщением «уровень / тема / поле» и инструкция `CONTENT.md`.
- Все файлы данных подключаются в `index.html` и грузятся при старте, даже если нужен один уровень. Ленивая загрузка по уровню возможна позже, но только через динамические `<script>`.
- Новый файл данных нужно вручную прописать в `index.html`. Если забыть, уровень будет пустым без ошибки в консоли.
- Файлы данных исполняются как код, поэтому доверие к ним такое же, как к коду сайта.
