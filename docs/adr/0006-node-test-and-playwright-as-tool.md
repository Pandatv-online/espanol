**Контекст**
Нужно проверять логику (квиз, выбор языка, хранилище, валидацию контента) и поведение интерфейса. При этом в проекте нет `package.json`-зависимостей и сборки (ADR 0001).

**Решение**
Логика без DOM проверяется встроенным `node --test` без сторонних пакетов. Для этого каждый модуль — IIFE, который регистрирует себя в `window.ECA` в браузере и в `globalThis.ECA` в Node. Поведение интерфейса проверяется Playwright по реальной странице (`tools/e2e.js`), только как инструментом разработки: в сайт он не входит.

**Почему**
- Jest/Vitest отвергнуты: они тянут `node_modules` и конфигурацию, а Vitest ещё и ожидает ES-модули, которые сайт не использует (ADR 0001).
- jsdom для тестов DOM отвергнут: это ещё один пакет, а поведение на `file://`, фокус, `prefers-color-scheme` и мобильную ширину он не воспроизводит. Настоящий браузер надёжнее.
- Вариант «только ручная проверка в браузере» отвергнут: при ~700 словах и 27 темах регрессии в квизе и хранилище руками не поймать.
- Playwright как часть проекта (тестовый раннер с CI) отвергнут: для одностраничной статики это лишняя инфраструктура. Достаточно скрипта-проверки.

**Последствия**
- Модули обязаны оставаться загружаемыми в Node: без обращений к `document`/`window` на верхнем уровне, с подменяемыми `localStorage` и генератором случайных чисел. Это ограничивает, как пишется код.
- `node --test` беднее Jest: нет встроенных моков DOM и снапшотов, подмены пишутся вручную.
- Playwright нужно ставить отдельно на машине разработчика. У автора контента его нет, поэтому e2e-проверка — забота разработчика, а не автора.
- Автоматического CI нет: тесты запускаются вручную.
